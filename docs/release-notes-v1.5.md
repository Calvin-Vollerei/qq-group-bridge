## QQ群文件搬运工 v1.5

本版修掉一个**让「优先执行」形同虚设**的问题，并补齐界面上几处会让人误解的地方。

---

### 下载哪个

| 文件 | 说明 |
|---|---|
| `qgb-v1.5-full.zip` | **推荐**。主程序 + NapCat 组件，解压即用（52 MB） |
| `qgb-v1.5-app-only.zip` | 只有主程序，NapCat 由你自行下载安装（22 MB） |
| `QQ群文件搬运工-解压我.zip` | 面向零基础用户的交付包：包名与目录全中文，内含《第一步看这里》《百度网盘授权怎么做》两份图文说明 |

**不需要安装 Python**：主程序自带 Python 3.11 运行时。系统要求 Windows 10/11 x64。

### 本版修了什么

**① 「筛选后优先执行，下载却没提前开始」—— 根因是队列被静默截断**

我给队列设了容量上限：只取**前 500 条**。而实际待处理有 **45,245 条**，
于是「优先执行筛选结果」只调整了前 500 条的**内部顺序** ——
你筛出来的文件如果排在第 3 万位，实际位置**毫无变化**。

修法：**去掉上限，全量排序**。实测 45,245 行全量取回 + 排序只要 **156 ms**，
成本可以忽略；同时把流水线每轮处理量从 50 提到 **200**，让优先项在一轮内就开始。

实测（真实库、5 万条待处理）：把**第 30,001 位**的文件优先执行 →
**661 ms 内移到第 1 位**，下一轮就会被搬。

**② 「刷新」按钮不见了 —— 实际是被挤出了窗口**

弹窗底部一排按钮右对齐 + 左侧信息标签过长，窗口宽度不够时最左边那个
（就是「刷新」）被顶到可视区外。

修法：「🔄 刷新列表」移到**左侧固定位置**，动作按钮成组右对齐。

**③ 筛选条件关掉窗口就重置**

筛选/排序状态原本是弹窗里的**局部变量**，关闭即销毁。
现在提到标签页实例上，**关闭再打开保留上次的筛选**。

**④ 「已见 / 待处理」是累计值，不是一次探测的数量 —— 你说得对**

这两个数来自库里的记录计数（累计），确实容易被当成"本轮扫描到多少"。

修法：

- 监控页统计区新增「**本轮新发现**」，它是**每轮扫描清零后重新累计**的，
  才代表"刚才这一轮扫到几个新文件"；
- 文件列表底部写明：`本表 N 项（其中待处理 M 项）｜累计：已见 X、待处理 Y、已搬完 Z｜本轮新发现 W`。

**⑤ 「当前筛选结果里没有『待处理』的文件」**

这条本身不是错误提示（很多情况下确实没有），但以前它和"筛选被截断"混在一起时
非常难懂。现在：筛选不再截断，且提示会明确说清是哪一种情况：

- 状态不是「待处理」→ "这一项状态是「已失败」，不是「待处理」，没有队列位置"；
- 已不在队列 → "点「🔄 刷新列表」后重试"；
- 真到边界 → "已经在队首/队尾，或不能跨越置顶边界"。

### 本版之前（v1.4）已包含

- **成批取不到下载直链**（`real fileUUID not found!`）：经真机探针确认，
  这是 NapCat 的 fileUUID 映射与会话状态脱节 —— 该映射**只对当前会话枚举过的
  文件有效**，失效时所有文件都取不到直链，但稍后能恢复。现在归类为
  **临时性故障**：退回待处理、**不消耗重试次数**、稍后自动重试
  （原来 `max_retries=1` 时一次就永久判死，导致 185 个文件全落失败）。
- 二维码「点了刷新不了」：改为**新的请求取代旧的**，点击后立刻有反馈。
- 下载卡住：读超时收紧为「卡死阈值」（默认 20 秒），实测从 105 秒降到 5 秒。
- 文件列表支持按状态 / 群聊 / 大小筛选、按名称/群号/大小/时间排序、搜索、置顶与上下移。

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可
- **升级旧版本时**：解压覆盖即可，**不要动 `data\` 目录**（凭据、群号、NapCat 运行时都在里面）；
  状态库会自动升级，旧数据不丢
- 想快速推进积压：进「文件列表」筛出想要的那批（按群聊/大小/状态），
  点「⤒ 优先执行筛选结果」，它们会立刻排到队首并在下一轮开始搬运

### 已知问题

- NapCat 的 fileUUID 映射可能与 QQ 服务端会话脱节（见上），根源在 NapCat 侧；
  本版保证"不卡死、可自动恢复"
- 百度网盘只保留最新一个 refresh token，重复获取会让旧的失效
- 待处理文件数量很大时（数万），列表首次打开需要约 0.3 秒排序，属正常
- 本项目未启用云端 CI：它是 Windows 专用工具，所有闸门在本机执行
  （373 项单元测试 + 离线端到端冒烟 + 源码扫密 + 界面结构检查）
