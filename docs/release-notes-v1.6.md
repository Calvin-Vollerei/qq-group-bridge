## QQ群文件搬运工 v1.6

本版处理"**待处理列表越积越多、下载始终不开始**"这个核心问题，并让文件列表窗口自适应屏幕。

---

### 下载哪个

| 文件 | 说明 |
|---|---|
| `qgb-v1.6-full.zip` | **推荐**。主程序 + NapCat 组件，解压即用（52 MB） |
| `qgb-v1.6-app-only.zip` | 只有主程序，NapCat 由你自行下载安装（22 MB） |
| `QQ群文件搬运工-解压我.zip` | 面向零基础用户的交付包：包名与目录全中文，内含《第一步看这里》《百度网盘授权怎么做》两份图文说明 |

**不需要安装 Python**：主程序自带 Python 3.11 运行时。系统要求 Windows 10/11 x64。

### 本版修了什么

**① 待处理列表是"历史累计"，不是"群里的实际文件"**

你说得对。`transfers` 记录**只增不减**：一次全量扫描会把群里所有文件都登记成
「待处理」，之后即使文件已从群里删除、或你根本不打算搬，记录也会一直留着。
实测你的库里积了 **48,035 条**「待处理」，最早的是**前一天**留下的。

**修法**：新增「**清空记录并重新发现**」按钮（监控页）。

- 清空「待处理 / 已过滤 / 失败」的累计记录；
- **保留已搬完的记录** —— 它们是去重依据，删掉会导致所有文件被重新下载上传；
- 然后点「立即刷新」重新扫描，待办列表就只反映**群内当前的文件**。

**② 「下载依然没有开始」——根因是上一版引入的副作用**

上一版把 `real fileUUID not found` 归为**临时故障**（不消耗重试次数）。
副作用是：这些**昨天的旧记录**每轮都失败、又不计次数，于是**下一轮立刻又排队首**，
把每轮的尝试名额全部吃掉 —— 真正的新文件永远轮不到。

**修法**：临时故障后加**冷却**（默认 300 秒，可在「高级」页调）：

- 冷却期内该项**不进待处理队列**，其它文件照常推进；
- 冷却到期后它自动回到队列，仍会重试（不丢文件）；
- 实测：3 个文件中给第 1 个设冷却 → 队列变成 `[f1, f2]`，冷却到期后回到 `[f0, f1, f2]`。

**③ 文件列表窗口不自适应、按钮被挡**

窗口原本写死 `1060x680`，窄屏上底部按钮会被挤出可视区。

**修法**：

- 窗口按**屏幕尺寸自适应**（宽 = 屏幕 92%，上限 1500px；高 = 屏幕 85%，上限 940px），
  并在屏幕居中偏上显示，最小尺寸 880×520；
- 列宽改为**文件名列伸缩**、其余列固定，不再写死后几列把内容挤出；
- 「🔄 刷新列表」仍在左侧固定位置。

### 本版之前（v1.5 / v1.4）已包含

- **优先执行真正生效**：队列原来被静默截断在前 500 条（实际待处理 4.5 万条），
  现在全量排序（实测 156 ms），第 30,001 位的文件可在 661 ms 内提到第 1 位；
  流水线每轮处理量 50 → 200。
- **临时性故障不卡死任务**：`real fileUUID not found!` 经真机探针确认是
  NapCat 的 fileUUID 映射与会话状态脱节（只对当前会话枚举过的文件有效），
  属可恢复故障，现在归为临时错误并自动重试。
- 二维码「点了刷新不了」→ 新的请求取代旧的，点击后立刻有反馈。
- 下载卡住：读超时收紧为「卡死阈值」（默认 20 秒），实测 105 秒 → 5 秒。
- 文件列表支持按状态 / 群聊 / 大小筛选、按名称/群号/大小/时间排序、搜索、
  置顶与上下移；筛选条件关闭窗口后保留。
- 监控页新增「本轮新发现」统计（区分累计与本轮）。

### 升级后建议的操作顺序

1. 关掉旧程序，用新的 `QQGroupBridge.exe`（或解压覆盖，**不要动 `data\` 目录**）；
2. 「监控」页点「**清空记录并重新发现**」；
3. 点「**🔄 立即刷新（拉取新文件）**」重新扫描；
4. 看「文件列表」里的待处理数量 —— 应该只反映群内**当前**的文件；
5. 想先搬哪批，就筛出来点「**⤒ 优先执行筛选结果**」。

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可

### 已知问题

- NapCat 的 fileUUID 映射可能与 QQ 服务端会话脱节，根源在 NapCat 侧；
  本版通过"临时错误 + 冷却"保证不卡死且能自动恢复
- 百度网盘只保留最新一个 refresh token，重复获取会让旧的失效
- 待处理数量很大时（数万），列表首次打开需约 0.3 秒排序，属正常
- 本项目未启用云端 CI：它是 Windows 专用工具，所有闸门在本机执行
  （381 项单元测试 + 离线端到端冒烟 + 源码扫密 + 界面结构检查）
