## QQ群文件搬运工 v1.2

本版聚焦三件**用户实际反馈**的问题：二维码刷不了、下载顺序想自己安排、下载卡住要久等。
另有一个我自己的脚本缺陷导致"越修越乱"的根因，也一并修掉了。

---

### 下载哪个

| 文件 | 说明 |
|---|---|
| `qgb-v1.2-full.zip` | **推荐**。主程序 + NapCat 组件，解压即用（52 MB） |
| `qgb-v1.2-app-only.zip` | 只有主程序，NapCat 由你自行下载安装（22 MB） |

**不需要安装 Python**：主程序自带 Python 3.11 运行时。系统要求 Windows 10/11 x64。

### v1.2 修了什么

**① 二维码「点了刷新不了」—— 根因是程序把它静默丢弃了**

- 单次取码最长要等 25 秒（HTTP 超时），而二维码只有约 30 秒时效，用户必然连点；
- 旧逻辑对"同名任务在跑"直接返回失败，**界面在这种情况下什么都不做** → 看起来像点了没反应；
- 现在改为**新的取代旧的**：连点会真的发出新请求，旧请求的结果自动丢弃，界面永远显示最新那张；
- 点击后**立刻**显示"正在获取二维码…（最长等 25 秒）"，按钮置忙；
- 失败提示追加"可以再点一次重试"，按钮也更名为「① 获取/刷新二维码」。

**② 下载顺序可以自己排（置顶 / 上移下移）**

- 入口：**监控页 →「查看搬运记录」**，弹窗顶部新增「下载顺序」区；
- 支持 ★置顶 / 取消置顶 / ↑上移 / ↓下移 / 刷新队列（双击也能置顶）；
- 顺序规则：**置顶 → 我排的顺序 → 没排过的按发现时间**；`上移/下移`不会越过置顶边界；
- **改完立即生效**：搬运线程每处理完一个文件就重新按当前顺序取队列，不用重启监控。

**③ 下载卡住不再久等，直接下一个**

- 原来靠 requests 的读超时（60 秒）兜底，服务器接了连接却不再发数据时，
  要等满 60 秒才报错，再乘重试次数 —— 实测**105 秒**才轮到下一个文件；
- 现在把**读超时收紧为「卡死阈值」（默认 20 秒）**，同样的场景 **5 秒**内就放弃并继续；
- 失败会被记录并稍后自动重试（不会丢文件）；阈值可在**高级页 →「下载卡死阈值（秒）」**调整（最低 5 秒）；
- 顺带说明：**"失败就继续下一个"本来就是既有行为**（流水线对每个文件独立 try/handle），
  本版解决的是"一次卡住拖很久"。

**④ 修掉我自己的一个脚本缺陷**

上一版我加的 `scripts/recover-napcat.py`（组件恢复工具）有两个错：

- 读 WebUI 配置时**少拼了一层 `config/`**，于是永远读到空值，导致每次运行都重新生成令牌 ——
  用户切回界面点「启动组件」时又变成不一致、又报「WebUI 令牌无效」；
- 现在改为**读旧值原样写回**（并已实测连续运行两次令牌不变）。

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可，
  已搬运的文件有去重记录，不会重复上传

### 已知问题

- NapCat 组件首次启动必须能访问外网；无法离线安装 QQ 运行环境
- 百度网盘只保留最新一个 refresh token，重复获取会让旧的失效
- 若「获取二维码」提示登录过于频繁，等 60 秒再点一次即可
  （本版已把 NapCat 的登录限流阈值从默认 3 次/分钟放宽到 10 次/分钟）
- 本项目未启用云端 CI：它是 Windows 专用工具，所有闸门在本机执行
  （355 项单元测试 + 离线端到端冒烟 + 源码扫密 + 界面结构检查）
