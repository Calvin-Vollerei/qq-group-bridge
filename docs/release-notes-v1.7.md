## QQ群文件搬运工 v1.7

本版修掉**「优先执行」完全没反应**（一个双重翻译的 bug）、**已上传文件被重复搬运**，
并补上置顶的绝对优先级与"扫描不叠加"的保护。

---

| 文件 | 说明 |
|---|---|
| `qgb-v1.7-full.zip` | **推荐**。主程序 + NapCat 组件，解压即用（52 MB） |
| `qgb-v1.7-app-only.zip` | 只有主程序，NapCat 由你自行下载安装（22 MB） |

**不需要安装 Python**：主程序自带 Python 3.11 运行时。系统要求 Windows 10/11 x64。

### 本版修了什么

**① 「优先执行筛选结果」永远提示"没有待处理"—— 我的 bug，双重翻译**

列表里存的状态已经是中文（"待处理"），而判断代码又拿它去查 `state_label`
（这个字典的键是 `discovered`）→ **永远查不到 → 永远判定为空**。
按钮等于摆设。

修法：判断一律使用**原始状态值**（在列表里随行隐藏保存），不再从显示文案反推。

**② 已上传的文件被重复搬运 —— `file_id` 不是稳定标识**

QQ 群文件的 `file_id` **会随会话/组件重启变化**。原来只按 `file_id` 去重，
于是组件重启后同一个文件被当成新文件，重新下载上传一遍。

修法：新增按 **(群, 文件名, 大小)** 的去重判断，扫描时先查一次。

> 注意语义：只认**真正搬成功的**（已完成/已上传）。被过滤或被跳过的**不算** ——
> 否者你改了过滤规则后，那些文件永远无法重新纳入。

**③ 置顶不够有效**

原来只把置顶项排到"手工排序段"之前，但队列里可能还有几百个更早的未排序项，
所以它仍然要等很久。

修法：**置顶项绝对优先** —— 每轮开始时把置顶的提到最前，未置顶的顺次后移。

**④ 有任务在跑时不再重复扫描**

一轮扫描/搬运还没结束时再点「立即刷新」，会让同一个群被重复枚举、同一批文件被
重复登记（与②叠加就是"重复搬运"）。

修法：

- `run_once` **不可重入**（带 `busy` 标志）；
- 「立即刷新」在一轮未结束时**明确提示**"当前一轮还没结束，已跳过这次刷新"，
  而不是静默什么都不做。

**⑤ 「已发现文件怎么还是累计的」—— 这是设计，但容易被误解**

两个数是不同性质，现在界面写清了：

| 显示 | 含义 |
|---|---|
「已见文件」 | **累计**：库里记录过的所有文件（含已过滤、已搬完的），用于判断"这个文件我见过" |
「待处理」 | **累计**：目前还没搬完的记录数 |
「本轮新发现」 | **每次扫描清零重算** —— 这才是"刚才这一轮扫到几个新文件" |

按你的要求，本版发布前**已帮你清空过一次累计记录**：清掉 68,874 条陈旧记录
（最早的是前一天留下的），保留 48 条已完成记录（去重依据）。清空后重新扫描
得到 1,386 条待处理，全部是当天新扫的。

### 本版之前已包含（v1.6 / v1.5 / v1.4）

- 「清空记录并重新发现」按钮（清空累计记录，保留已完成去重记录）
- 临时性故障（`real fileUUID not found`）加**冷却**，不再霸占队首
- 队列不再被静默截断（原 500 条上限 → 全量排序），「优先执行」真正生效
- 文件列表：筛选（状态/群聊/大小）+ 搜索 + 排序 + 置顶/上下移，窗口自适应
- 二维码「点了刷新不了」→ 新的请求取代旧的，点击后立刻有反馈
- 下载卡住：读超时收紧为「卡死阈值」（默认 20 秒），实测 105 秒 → 5 秒
- 监控页新增「本轮新发现」，区分累计与本轮

### 建议操作顺序

1. 关旧程序，用新的 `QQGroupBridge.exe`（或解压覆盖，**不要动 `data\` 目录**）
2. 「监控」页点「🔄 立即刷新（拉取新文件）」—— 若提示"当前一轮还没结束"，等它跑完再点
3. 进「文件列表」，筛出想先搬的那批 → 点「**⤒ 优先执行筛选结果**」
4. 「监控」页点「▶ 开始监控」

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可

### 已知问题

- NapCat 的 fileUUID 映射可能与 QQ 服务端会话脱节，根源在 NapCat 侧；
  本版通过"临时错误 + 冷却"保证不卡死且能自动恢复
- 百度网盘只保留最新一个 refresh token，重复获取会让旧的失效
- 本项目未启用云端 CI：它是 Windows 专用工具，所有闸门在本机执行
  （391 项单元测试 + 离线端到端冒烟 + 源码扫密 + 界面结构检查）
