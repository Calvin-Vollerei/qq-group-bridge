## QQ群文件搬运工 v1.4

本版修掉一个**会让整批任务卡住**的真实故障，并把文件列表补成"可筛选、可排序、
可优先执行"的完整面板。

---

### 下载哪个

| 文件 | 说明 |
|---|---|
| `qgb-v1.4-full.zip` | **推荐**。主程序 + NapCat 组件，解压即用（52 MB） |
| `qgb-v1.4-app-only.zip` | 只有主程序，NapCat 由你自行下载安装（22 MB） |

**不需要安装 Python**：主程序自带 Python 3.11 运行时。系统要求 Windows 10/11 x64。

### 本版修了什么

**① 一批文件全部「取不到下载直链」，任务不再推进 —— 根因与修法**

症状：日志里成批出现

```
失败（已重试 1 次）：xxx.pdf —— 无法获取下载直链：get_group_file_url: real fileUUID not found!
```

真机探针查清了根因：NapCat 取直链依赖它内部的 **fileUUID 映射**，而该映射
**只对当前会话里枚举过的文件有效**。映射失效时，`get_group_file_url` 对
**所有**文件都回这句错 —— 实测包括**之前成功下载过**的文件。

- 换动作名、去掉 `busid` 都一样失败 → **不是参数问题**；
- 但**刚枚举过的文件能立刻取到真直链** → 说明是会话状态问题，**可恢复**。

当时它被当成普通失败：`max_retries=1` 时**一次就永久判死**，于是 185 个文件
全落「失败」，看起来像"任务卡住不推进"。

**修法：把它归类为「临时性故障」**（新增 `TransientError`）：

- 退回待处理、**不消耗重试次数**、稍后自然重试；
- 日志提示改为「暂时跳过（稍后自动重试）」，并说明可重启 QQ 组件；
- 已在处理中的文件仍会走完当前批，不影响后续文件。

**已判为「失败」的历史文件不会自动重试** —— 到「监控」页点一次
「重试失败项」即可把它们复位成待处理，然后会正常搬运。

**② 文件列表：筛选 + 排序 + 优先执行**

监控页 →「📋 文件列表 / 下载顺序」：

- **搜索框**：按文件名或**群号**即时筛选；
- **筛选**：按**状态**（待处理/下载中/上传中/已完成/失败/已过滤）、
  按**群聊**（下拉自动列出你配置的群）、按**大小**（<1MB / 1–10MB / 10–100MB / ≥100MB）；
- **排序**：下载顺序 / 文件名 / 群号 / 大小 / 上传时间 / 处理时间，可切**倒序**；
  点**列标题**同样能排序；
- **★置顶 / 取消置顶 / ↑上移 / ↓下移**（双击置顶）：只对「待处理」行生效；
- **⤒ 优先执行筛选结果**：把当前筛选出的待处理项**按显示顺序提到队首**，
  置顶项仍保持最前。可以"筛一批、优先一批"，实现分批推进；
- 改完**立即生效**，监控不用重启。

**③ 修掉误导人的提示**

原来无论什么原因都提示"已经到边界了，或该项不支持该操作"。现在会区分：

- 状态不是「待处理」→ 明确说"它是「已失败」，没有队列位置，请先点「重试失败项」"；
- 该行已不在待处理队列里（刚被搬走）→ 提示"点「🔄 刷新」后重试"；
- 真的在队首/队尾或不能跨越置顶边界 → 才提示"已经在队首/队尾"。

**④ 上一版已包含（v1.3）**

- 二维码「点了刷新不了」→ 新的请求取代旧的，点击后立刻有反馈；
- `max_retries=1` 时一次失败即判死是配置问题 —— 可在**高级页**把
  「单文件最大重试次数」调到 2–3（默认 2）；
- 下载卡住：读超时收紧为「卡死阈值」（默认 20 秒），实测从 105 秒降到 5 秒；
- NapCat 登录限流阈值从 3 放宽到 10 次/分钟。

### 关于「real fileUUID not found」的根治

本版让它**不再把任务卡死**（临时故障 → 自动重试）。若你发现**长期**
大量出现这一条，说明 NapCat 的映射一直没恢复，此时最有效的操作是：

1. 「QQ 登录」页点「停止」→ 再「启动组件」重启一次组件；
2. 回「监控」页点「重试失败项」；
3. 若仍持续，请把「高级」页的**单文件最大重试次数**设为 3 再观察。

> 这一条属于 NapCat 与 QQ 服务端之间的会话状态问题，本项目无法从外部修复，
> 只能保证「不因此卡住任务、且能自动恢复」。

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可
- **升级旧版本时**：解压覆盖即可，**不要动 `data\` 目录**（凭据、群号、NapCat 运行时都在里面）；
  状态库会自动升级，旧数据不丢

### 已知问题

- NapCat 的 fileUUID 映射可能与 QQ 服务端会话脱节（见上），表现为成批取不到直链；
  本版已保证"不卡死、可自动恢复"，但根源在 NapCat 侧
- 百度网盘只保留最新一个 refresh token，重复获取会让旧的失效
- 本项目未启用云端 CI：它是 Windows 专用工具，所有闸门在本机执行
  （366 项单元测试 + 离线端到端冒烟 + 源码扫密 + 界面结构检查）
