本版修掉**上传偶发 405**、让**优先/置顶真正独占第一批**，并让文件列表窗口适配多屏。

### ① 上传报「服务器返回 405」—— 不是权限问题，是偶发拒绝

用 OpenList 的访问日志做了对照统计：

| 结果 | 数量 |
|---|---|
`201`（上传成功） | **1,881** |
`405`（被拒） | **99**（约 5%） |

**同一个群、同一个目录里既有大量成功、也有零星失败**；而且把成功与失败的**文件名特征**
逐项对比（长度、空格、中文标点、括号、非 ASCII 比例）**两组几乎一致** ——
所以既不是权限问题，也不是文件名不合法。

结论：这是网盘驱动侧的**偶发拒绝**（限流/上游抖动）。

**真正的问题是处理方式**：你的配置里 `单文件最大重试次数 = 1`，等于**一次失败就永久判死**。

修法：

- 405 归类为**可重试的临时故障**（提示里说明可能是限流/空间不足）；
- 默认重试次数 **2 → 3**；
- 你机器上的配置已帮你从 **1 改成 3**（原文件已备份为 `_config-backup-*.json`）；
- 顺手把「下载卡死阈值」从 10 秒放宽到 20 秒，并把新增字段补进配置。

> 之前的 99 条失败项：到「监控」页点「**重试失败项**」即可复位重搬。

### ② 「优先下载、置顶下载还是不起效果」

排序本身没坏。问题是每轮会处理 **200 个**待处理项，置顶项虽然排在第一位，
却和 199 个普通项**混在同一批**里跑 —— 你盯着日志看到前面几十条都是别的文件，
主观感受就是"没效果"。

**修法**：**置顶/优先项独占第一批**。点完「⤒ 优先执行筛选结果」后，
下一轮**只跑你选的那批**（通常几个到几十个），跑完再继续其余文件。

### ③ 「拓展窗口不能自适应 Win 的多窗口」

原来只按**主屏**尺寸算（`winfo_screenwidth()` 在多屏下只反映主屏），
窗口会被放到别的屏或屏外，拉伸也不跟着变。

**修法**：

- 以**主窗口当前所在显示器**的可用区域为准来定尺寸与位置；
- 跟随 Tk 的 DPI scaling（缩放 125%/150% 时不会过小或过大）；
- 显式允许自由缩放与最大化，列宽按 stretch 分配（文件名列占剩余空间）。

### 上一版（v1.8）已修：下载起不来的真正根因

真机探针实测：库里存的 `file_id` **全部失效（命中率 0%）**，但文件本身还在群里
（按文件名命中 50–100%），而用当前列表里的 id 取直链是成功的。
根因是 `transfers.file_id` 在登记那刻固定、而群文件 id 会变。
现在下载前会用 **(文件名, 大小)** 解析出**当前有效**的 id 再取直链。

### 建议操作顺序

1. 关旧程序，用新的 `QQGroupBridge.exe`（或解压覆盖，**不要动 `data\` 目录**）
2. 「监控」页点「**重试失败项**」（把之前 405 失败的那批复位）
3. 进「文件列表」筛一批 →「⤒ 优先执行筛选结果」→ 回监控页看日志，**这一轮就只跑你选的那批**
4. 「监控」页点「▶ 开始监控」

### 重要提醒

- 本包**不含**任何凭据、群号、网盘账号；凭据只在本机用 Windows DPAPI 加密保存
- 本包**不含**腾讯客户端二进制，QQ 运行环境由 NapCat 官方安装器在首次启动组件时下载
- NapCat 是非官方 QQ 客户端，**请用专用小号**，保持默认轮询间隔；账号风险自担
- 未做代码签名，首次运行可能被 SmartScreen / 杀毒软件拦截，选「允许」即可
- OpenList 的百度驱动有**单文件 2 GB 上限**，群里有超大文件时请把「最大体积」设为 1900 MB
- 电脑需保持开机不休眠；关机后重新双击 `启动搬运工.bat` 并点「开始监控」即可
